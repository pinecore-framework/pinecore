# Версии и релизы

Репозиторий — [github.com/pinecore-framework/pinecore](https://github.com/pinecore-framework/pinecore), ветка одна — `main`.
Пакет — [`pinecore/pinecore`](https://packagist.org/packages/pinecore/pinecore) на Packagist; Packagist обновляется
хуком GitHub на каждый push и тег, ручных действий нет.

## Как потребитель фиксирует версию

Только через Packagist и только на теги:

```bash
composer require pinecore/pinecore:^0.1
```

- Секция `repositories` (path / vcs) и symlink'и на локальный клон в проекте-потребителе не используются.
- `minimum-stability: dev` и `dev-main` не нужны: `dev-main` — это незарелизенный HEAD, он не гарантирует ничего.
- Composer ставит dist-архив с GitHub — git-доступ к репозиторию серверу потребителя не нужен.

## Схема версий

SemVer, пока в `0.x`:

| Изменение | Версия | Попадает под `^0.1` |
|---|---|---|
| Фикс, новая возможность без поломки API | патч: `0.1.0` → `0.1.1` | да, по `composer update` |
| Ломающее изменение (сигнатура, поведение, конфиг) | минор: `0.1.x` → `0.2.0` | нет, потребитель меняет constraint сам |

В `0.x` каретка фиксирует минор (`^0.1` = `>=0.1.0 <0.2.0`), поэтому ломающие изменения идут только в минор.
`1.0.0` — когда публичный API устоится; дальше обычный SemVer (ломающее — в мажор).

## Цикл «правка фреймворка → потребитель»

1. Правка в pinecore, тесты зелёные, коммит в `main`, push.
2. Релиз — тег с заметками (что изменилось; для минора — что сломано и как мигрировать):

   ```bash
   gh release create v0.1.1 --target main --title v0.1.1 --notes "..."
   ```

   Тег — `vX.Y.Z`, всегда на коммите из `main`. Опубликованный тег не перевешивается: ошибка в релизе — это
   следующий патч.
3. Packagist подхватывает тег сам (обычно в пределах минуты).
4. В потребителе: `composer update pinecore/pinecore`; для нового минора — сначала поднять constraint
   (`composer require pinecore/pinecore:^0.2`). `composer.lock` потребителя коммитится — на прод едет ровно
   зафиксированная версия.

Нужна незарелизенная правка в потребителе — выпускается патч-релиз; path-репозиторий и `dev-main` для этого не
заводятся.
